# 依賴安全性評估與逐步升級策略報告

本報告針對 `GameServer` 目前使用的 Maven 依賴進行安全性審查。目前多個核心組件存在嚴重的安全漏洞（CVE），且版本落後多年。

## 1. 核心評估原則
- **Java 1.8 相容性**：所有建議版本必須支援 Java 1.8，並預留未來遷移至 Java 11/17/22 的路徑。
- **穩定優先**：每次僅升級一個組件，通過編譯並確認執行 Jar 正常後才進行下一個。
- **風險導向**：優先處理具有 RCE (遠端代碼執行) 風險的組件。

## 3. 技術分析專題

### 3.1 日誌系統的關係 (JCL vs Log4j vs SLF4J)
專案中同時出現這三者是歷史遺留問題。它們的關係如下：
- **SLF4J (現代外殼)**：目前專案的核心日誌介面，應以此為準。
- **Commons-Logging (JCL - 舊外殼)**：被許多舊函式庫使用，應透過 `jcl-over-slf4j` 橋接到 SLF4J。
- **Log4j (舊引擎)**：存在重大安全漏洞，未來應改用 **Logback** 並透過 `log4j-over-slf4j` 橋接，以確保不需改動舊代碼。

### 3.2 輔助工具類組件分析
- **JNA (Java Native Access)**：用於呼叫系統底層 DLL (如 HWID 綁定)。5.8.0 存在 DoS 崩潰風險，建議升級。
- **Javolution**：早期用於解決 Java 集合性能不足的工具。在現代 JVM (Java 8+) 中，其重要性已降低。因 API 遷移成本過高，建議僅在核心性能瓶頸處保留。

## 4. 未來 Java 版本相容性提醒 (11/17/22)
- **Fastjson 2.x**：是適配 Java 17+ 新特性的關鍵。
- **MySQL Connector 8.4+**：已為 Java 22 做好準備。
- **Logback**：比 Log4j 更能適配 Java 11+ 的類別載入架構。
