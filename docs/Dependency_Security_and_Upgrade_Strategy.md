# 依賴安全性評估與逐步升級策略報告

本報告針對 `GameServer` 目前使用的 Maven 依賴進行安全性審查。目前多個核心組件存在嚴重的安全漏洞（CVE），且版本落後多年。

## 1. 核心評估原則
- **Java 1.8 相容性**：所有建議版本必須支援 Java 1.8，並預留未來遷移至 Java 11/17/22 的路徑。
- **穩定優先**：每次僅升級一個組件，通過編譯並確認執行 Jar 正常後才進行下一個。
- **風險導向**：優先處理具有 RCE (遠端代碼執行) 風險的組件。

## 3. 詳細說明與建議

### 第一階段：處理即時危險 (RCE 漏洞)

#### 1. Fastjson (Priority: 1)
- **現狀**：1.2.x 分支已多次爆出繞過 AutoType 限制的 RCE 漏洞。
- **建議**：雖然 1.2.84 是安全版，但強烈建議跳轉至 **2.x 系列**。
- **注意**：2.x 的 Package 名稱不同，需進行全專案搜索替換。

#### 2. Log4j 1.2.x 遷移 (Priority: 2)
- **現狀**：Log4j 1.x 自 2015 年起已停止維護。它不支援現代 Java 功能且有安全漏洞。
- **建議**：不要升級到 Log4j 2.x（配置過於複雜），建議遷移至 **SLF4J + Logback** 架構，這是目前 Java 社群的主流標準。

#### 3. Mina Core (Priority: 3)
- **現狀**：2.2.2 存在反序列化漏洞。
- **建議**：升級至 **2.2.9**，這是針對 Java 8 維護的最新安全版本，改動最小。

### 第二階段：結構化調整

#### 4. Netty 3 to 4 (Priority: 5)
- **現狀**：Netty 3 與 Netty 4 的架構完全不同（Package 名稱從 `org.jboss.netty` 改為 `io.netty`）。
- **風險**：這是對伺服器網路層的核心改動，必須放在中後期單獨處理，並進行大量的壓力測試。

#### 5. MySQL Connector (Priority: 6)
- **建議**：從 5.1.x 直接跳轉到最新的 **26.x.x** 系列。
- **注意**：Driver 類別名稱可能從 `com.mysql.jdbc.Driver` 變更為 `com.mysql.cj.jdbc.Driver`，且時區處理 (serverTimezone) 變得嚴格。
