2. 數量差異的原因解析
•
輔助性 Table (無對應 Template)：
◦
例如 SqlError.java (紀錄錯誤)、BadIpDatabase.java (黑名單)、LogChatTable.java (對話紀錄)。
◦
這些 Table 主要是執行 INSERT 動作或簡單的查詢，不轉換為複雜物件，因此在 templates 資料夾中找不到對應的 POJO。
•
多對一關係：
◦
例如 ItemTable 下面可能細分了 etcitem、weapon、armor 三張 SQL 表，但它們在 Java 記憶體中最後都繼承或轉換自 L1Item 體系。
•
功能工廠 (Factories)：
◦
例如 FinalKillDropFactory.java，它是一個邏輯處理器而非單純的 DAO，但被放在 datatables 目錄下。
3. 「轉換邏輯」抽離的可行性評估
評估結論：完全可行，且這是模組化的「必經之路」。
抽離方案：
我建議為這 71 個 Template 建立專屬的 RowMapper。
•
優點 1：GameServer 邏輯層將不再看到 rs.getInt("npc_id") 這種代碼。
•
優點 2：如果您將 sql 的 Table 換成 SQLite 版，您只需要重寫 SQL 語句，而資料如何「填進」Template 的邏輯（Mapper）是可以完全複用的。
