# ThorLineageServer

本專案旨在修復並現代化一個早期的 Lineage (天堂) 遊戲伺服器核心，使其能夠在現代開發環境中穩定編譯與運行。

## 1. 專案背景與恢復過程

本專案是基於遺留的原始代碼與運行環境資源重新構建而成。

### 恢復與現代化改動
為了提升開發效率與長期維護性，本專案在人工與 AI Agent 的協助下完成了以下遷移：
*   **架構遷移**：將原本不完整的代碼結構重組為 **Gradle 多模組架構**。
*   **構建系統**：由傳統編譯方式遷移至 Gradle，並使用 Version Catalog (`libs.versions.toml`) 統一管理所有依賴項。
*   **編譯環境**：全面適配 **Java 1.8 (JDK 8)**，確保與核心邏輯的相容性。
*   **混淆集成**：集成了 Allatori 混淆器，可透過自動化指令產出受保護的 JAR 檔案。

## 2. 專案結構說明

*   `GameServer/`: 核心伺服器邏輯模組 (純 Java 1.8)。
*   `javafx/`: 提供特定 UI 工具類支援。
*   `runtime/`: 遊戲伺服器執行環境與工作目錄。
*   `docs/`: 包含技術文檔（如混淆指南、依賴修復說明）。

## 3. 運行環境配置指南 (關鍵步驟)

由於版權與資源體積限制，Git 倉庫**不包含**任何遊戲運作所需的數據資源檔案。**你必須自行取得原始資源檔案，並依照以下說明完整配置至 `runtime/` 目錄，否則伺服器將無法正常啟動。**

### 詳細資源放置清單：

| 目錄路徑 | 建議放置內容說明 | 詳細用途 |
| :--- | :--- | :--- |
| `runtime/Config/` | 所有 `.properties` 配置文件 | 包含資料庫連接 (`db.properties`)、伺服器倍率、網路連接設定等核心配置。 |
| `runtime/Data/` | XML 數據檔或二進位數據檔案 | 包含 NPC 模板、道具屬性、怪物 AI、魔法效果等遊戲核心邏輯數據。 |
| `runtime/maps/` | 遊戲地圖圖層與座標數據 | 伺服器校驗玩家移動、地圖障礙與視線判斷所需之數據檔。 |
| `runtime/` | SQL 數據庫初始化腳本 | 用於建立遊戲資料庫架構與導入初始數據，通常為 `.sql` 檔案。 |
| `runtime/loginfo/` | (目錄) 伺服器運行日誌儲存處 | 系統運行時會在此產生 log 檔案，已預設建立目錄。 |

**操作提示**：
*   請確保 `Config/` 目錄下的路徑與文件名完全對應，不要遺漏任何配置文件。
*   資料庫腳本需手動導入您的資料庫（建議使用 MySQL 5.x 版本）。
*   `runtime/` 下的各個子目錄已預留 `.gitkeep` 檔案，請勿隨意刪除。

## 4. 開發與測試指令

### 編譯、混淆並部署
```bash
./gradlew :GameServer:runAllatori
```
此任務會執行完整建置流程：編譯代碼 -> 執行 Allatori 混淆 -> 將產出的 `GameServer.jar` 自動部署至 `runtime/` 目錄。

### 啟動測試伺服器
```bash
./gradlew :GameServer:runGameServer
```
此指令會以 `runtime/` 為工作目錄，直接運行該目錄下的 `GameServer.jar`。
